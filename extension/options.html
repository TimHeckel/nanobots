nanobots — options

Fine-grained PAT with Issues: write + Contents: write on your target repos (or a classic PAT with repo). Stored locally in this browser profile only.
Screenshots upload to your R2 bucket and the issue embeds the link — nothing is committed to git. Screenshot capture stays disabled until these four fields are filled; reports file text-only in the meantime.
how to get these (≈3 minutes, free)
  1. Sign up / log in at dash.cloudflare.com (free account). R2's free tier — 10 GB storage, ~1M uploads/month, zero egress fees — is far more than screenshot traffic needs. Cloudflare may ask for a card to enable R2; you won't be charged within the free allowance.
  2. Sidebar → R2 Object Storage → Create bucket, name it e.g. nanobots-shots. → bucket field.
  3. On the bucket's Settings tab → Public access → enable the r2.dev subdomain (or connect a custom domain). Copy the URL it shows (like https://pub-xxxx.r2.dev) → public base url field. Note: anything in this bucket is publicly reachable by URL — fine for screenshots you're filing to a repo anyway.
  4. Back on the R2 overview → Manage R2 API Tokens → Create token with Object Read & Write, scoped to your bucket. Copy the Token Value (not the S3 keys) → api token field.
  5. Your account id is shown on the R2 overview page (right side) or in the dashboard URL.
Any OpenAI-compatible endpoint: Anthropic https://api.anthropic.com/v1 · OpenAI https://api.openai.com/v1 · Gemini https://generativelanguage.googleapis.com/v1beta/openai · OpenRouter https://openrouter.ai/api/v1 · local Ollama http://localhost:11434/v1.
The agent needs vision + function calling — vision to read your screenshots, tools to search the repo and file reports. Solid picks: claude-sonnet-5 (default) · via OpenRouter: xiaomi/mimo-v2.5 (~$0.1/M, the budget standout), stepfun/step-3.7-flash, minimax/minimax-m3, google/gemini-2.5-flash. Text-only models (DeepSeek, Hy3, GLM) can chat and file, but can't see images.
